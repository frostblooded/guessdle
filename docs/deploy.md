# Deploy (home server)

- Push to `prod` triggers the self-hosted runner (label `home-server`), which runs `./deploy/start.sh`: `git pull --ff-only`, then `docker compose -f deploy/compose.prod.yaml up -d --build`.
- Four compose services: `web` (nginx, container `guessdle-server`, port 8080), `api` (Express, port 3000, internal only), `db` (Postgres 17, named volume `db-data`, no published port) and `backup` (below). nginx proxies `/api/` to `api`. The Cloudflare tunnel service is `http://guessdle-server:8080` (public URL https://guessdle.niki.casa/).
- Only `web` joins the external Docker network `immich_default`, the one `cloudflared` is on. The immich stack creates it, so immich must be up first. `api` and `db` sit on the private `internal` network.
- Secrets: untracked `deploy/.env` on the server (copy `deploy/.env.example`). Required keys: `POSTGRES_PASSWORD`. Sign-in mail keys: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `PUBLIC_URL` (`https://guessdle.niki.casa`, used in the emailed link) and `ADMIN_EMAILS` (comma-separated; these emails become admins on sign-in, never demoted by the list). Without `SMTP_HOST`/`PUBLIC_URL` `POST /api/auth/email/request` answers 503 `login_unavailable` and anonymous play still works. See Email sign-in below. The API gets `DATABASE_URL` from compose; `api` runs pending migrations (`db/migrations/*.sql`) at startup.
- Sessions: opaque cookie token (HttpOnly, Secure, SameSite=Lax), hash stored in the `sessions` table, 30-day rolling lifetime. Revoke with `delete from sessions where user_id = ...`; it takes effect on that user's next request. `Secure` needs the site served over HTTPS (the tunnel does).
- Abuse limits (starting values, tunable after launch): nginx (`deploy/nginx.conf`) allows 60 requests/min per IP with burst 30 on `/api/` and 10/min burst 5 on `/api/auth/email*`, answers 429 plain text, caps bodies at 10 KB, and takes the real client IP from `CF-Connecting-IP` only from private networks. Express allows 120 requests/min per signed-in user (per IP when anonymous; `trust proxy` is one hop), answers 429 JSON `rate_limited`; override with `RATE_LIMIT_MAX` and `RATE_LIMIT_WINDOW_MS`. JSON bodies are capped at 10 KB and `grade`/`merge` reject more ids than the roster. Validate nginx edits with `docker run --rm -v "$PWD/deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro" --add-host api:127.0.0.1 nginx nginx -t`.
- Backups: The fourth service `backup` (nightly dump, 14 daily + 8 weekly retention, weekly restore test, status file) writes to the named volume `backups`, which `api` mounts read-only. Restore, re-seed and status format: [backup-runbook.md](backup-runbook.md). The admin panel's BACKUPS tab reads `status.json` and `daily/` through `GET /api/admin/backup` (red past 36 hours, on a failed dump or restore test, or when the dump files are missing); `BACKUP_DIR` overrides the mount path (default `/backups`, no setting needed in compose).
- Health: `curl http://localhost:3000/api/health` inside the api container, or `/api/health` through the site; 503 means the API cannot reach Postgres.
- "Bad gateway" → run `docker inspect guessdle-server` and `docker inspect cloudflared_tunnel`; both must list the same network under `Networks`.
- GitHub Pages only serves `deploy/redirect.html` to the home server (ADR 0005).

## Email sign-in (production)

- Production sends through a dedicated Gmail account: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587` with `SMTP_SECURE=false` (STARTTLS, which the mailer requires for any non-local host; port 465 with `SMTP_SECURE=true` also works), `SMTP_USER=<account>@gmail.com`, `SMTP_PASS` a 16-character Google App Password (needs 2-Step Verification on the account; the normal password does not work), `SMTP_FROM="Petdle <account>@gmail.com"` (Gmail rewrites other From addresses).
- Gmail allows roughly 500 recipients a day; the per-address limits (1/minute, 5/hour) and nginx limits keep sign-in mail well under it for a small game.
- Deliverability: mail from Gmail itself passes SPF and DKIM. If `SMTP_FROM` moves to your own domain, publish SPF and DKIM records for it, or sign-in links land in spam.
- Links expire after 15 minutes and work once. Check delivery with `docker compose -f deploy/compose.prod.yaml logs api` (send failures log and answer 503).

## Local development

- `docker compose up -d db`, copy `.env.example` to `.env`, then `npm run build && npm start`: one Node process serves the page and `/api`. For sign-in locally, `docker compose up -d mailpit` and keep the `SMTP_*`/`PUBLIC_URL` defaults from `.env.example`: mails land in the inbox at http://localhost:8025. `docker compose up` (dev container) starts Mailpit itself and points the container at it (`SMTP_HOST=mailpit`, `PUBLIC_URL=http://localhost:8080`), so sign-in works with no setup. Without `SMTP_HOST` the request route answers 503 `login_unavailable`.
- `npm run test:integration` needs Docker (Testcontainers starts Postgres itself).
- Dev compose and prod compose both publish Postgres/ports on this machine: a leftover `deploy-db-1` (prod stack) makes `docker compose up` fail with a port-in-use error, and the dev app then cannot resolve host `db`. Run `docker compose -f deploy/compose.prod.yaml down` first, then `start_dev.bat`.
- Git Bash mangles `-v "$PWD/...:/..."` paths into a junk directory (once created `deploy/nginx.conf;C`). Prefix `docker run` with `MSYS_NO_PATHCONV=1` or run it from PowerShell.
